# Web MVP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a local browser UI over trusted Candidate v2 query APIs so the user can visually inspect Today, Candidates, Stock Profile and Strategy Screener without using the CLI.

**Architecture:** A small React + TypeScript + Vite SPA consumes FastAPI only. The browser never reads files/DuckDB and never recomputes ranking or selection. Candidate order comes from the stored Candidate snapshot; client-side filters only hide rows and never alter rank.

**Tech Stack:** Node 22, React, TypeScript, Vite, React Router, native fetch, CSS, Vitest, Testing Library.

**Spec:** `docs/superpowers/specs/2026-09-21-production-candidate-v2-web-mvp-design.md`

## Global Constraints

- Plan A must be complete first.
- FastAPI remains the only data source for Web.
- Web is strictly read-only in this MVP.
- No state-management library.
- No UI framework.
- No trading/buy/sell language.
- No client-side Factor/Strategy/Candidate recomputation.
- Candidate stored order is authoritative.
- Responsive minimum: desktop 1280px and tablet 768px.
- Chinese UI labels; enum values may retain English domain vocabulary.

## Review Focus

1. No Candidate snapshot for selected date → explicit “该日期尚未发布候选池”, not a blank page.
2. API timeout/500 → error panel with retry; stale data must not masquerade as current data.
3. Candidate with `TREND_WEAKEN` risks → visible risk badge/text above fold.
4. Browser filter changes visible rows only; rank numbers remain original stored ranks.
5. No stored Candidate dates → onboarding empty state, not an exception.
