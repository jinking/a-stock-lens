## 四、审查时必须指出的旧计划问题

1. `normalize_stage()` 返回 `NormalizeOutcome`，不是只有 `NormalizedDataset`。名单在 `outcome.securities`，财务质量报告、解析错误、缺失数据集在其他字段；四张值表不能替代全部结果。
2. 原领域记录没有统一 `status` 列；财务与行情状态部分在 QualityReport 中。不能给所有行补 `VALUE` 或把缺失统一改成 `NULL`。
3. 当前 `run_research_analysis()` 会重复调用归一化。迁移读路径必须贯通 CLI、研究池、全量分析、daily，而不是只改一个函数默认参数。
4. `JobStore` 按日期保存、按首次插入顺序展示、同阶段重录保持位置。仅 `(job_type, as_of, payload)` 不足以保存顺序。
5. 已有 DuckDB 的查询方法含 `CREATE TABLE IF NOT EXISTS`；正式切换前要修成真正只读并在损坏时显式失败。
6. 五只标的旧快照必须原样迁入，不能让同日全池重算覆盖它。历史重新分析使用隔离数据库；不能把 9 月 17 日数据伪装成另一个日期。
7. 不双写方案下，切回 JSON 会漏掉切换后的 Watchlist/Job 更新；必须有当前状态反向导出和比对步骤。
8. 旧计划引用的 167,751 行已过时；本机说明书后来记录 1,675,723 行。执行时用文件哈希与实读计数，不硬编码任一数字。

## 五、存储决策包：具体建议与批准状态分开

`docs/STORAGE.md` §6 明确写道：“以上四项未确认前，实施计划按‘不预设’处理，对应的任务保持 `BLOCKED`。”旧计划亦将布局、迁移历史、双写、因子归属列为 STOP GATE。
本轮用户明确确认的是**迁移进入第二阶段**，没有逐项确认下面四个选项。以下给出完整建议，使下一位 AI 能一次性提交确认材料；不得把本计划的建议写成已经批准。

| 决策 | 推荐方案 | 理由与影响 | 未确认时的执行边界 |
| --- | --- | --- | --- |
| S1：布局与分区 | `storage.parquet_root/normalized/v1/<as_of日期>/<bundle_id>/`；每个数据表一个 Parquet 文件；同日可有多个不可变批次，以显式批次指针选读 | 第一版按分析时点生成完整数据包，便于验证和回滚；会重复保存历史窗口，后续再按证据优化 | 可完成契约、转换器、临时目录测试；不发布正式布局 |
| S2：因子存放 | Normalized 只存基础数据及质量/行业证据；Factor/Strategy 结果作为正式快照进 DuckDB | 避免双份因子时序和事实边界混乱 | 不新增归一化因子表 |
| S3：既有状态 | JSON 快照、Watchlist、Job 全量复制到新 DuckDB；原文件只读保留；冲突阻断 | 保持历史和研究记录连续 | 可完成导入器与演练；不切生产库 |
| S4：切换策略 | 不长期双写；影子生成、双读比对后，在暂停写入的窗口统一切换；反向导出支持回滚 | 避免两套业务状态逐渐分叉 | 可完成演练；不变更生产默认 |

附属工程建议：PyArrow 默认压缩参数显式固定为 `snappy`，每次写入最多 65,536 行一批，不额外调 row group；这些是可替换的工程参数，不是选股阈值。旧文档也将压缩参数标为未确认，提交 S1 时一并说明并记录裁决。

## 六、共同测试与任务交付格式

每个子计划的代码任务都执行：

```bash
uv run pytest <该任务列出的测试文件> -q
uv run ruff check .

git diff --check
```

这里的测试文件参数按子计划中的实际命令替换；不得把尖括号示意文字直接作为 shell 命令。
