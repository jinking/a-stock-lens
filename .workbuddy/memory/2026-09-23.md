## Progress 累计显示补丁

- 用户反馈：进度条从 `1/4168` 起跳，怀疑之前下载过的 1400 只又被重新拉。事实是 `_land_dataset` 已经把它们从 wanted 里 skipped 掉，但 progress 回调分母是 wanted 子集（4168）而不是 listing 全集（5568），所以用户看不到"前 1400 只已落地"这件事——这是 UI 表达错误，不是技术重下。
- 修复：给 `DataProvider.fetch` 协议加 keyword 参数 `prior_landed: int = 0`，让两个 bulk provider（`AkShareProvider`、`WestockBarsProvider`）和两个 stub（`LocalCsvProvider`、`WestockCliProvider`、`NeodataProvider`）都接住——fetch 不发 progress 时直接 `del prior_landed`。
- `_land_dataset` 把 `len(skipped)` 作为 `prior_landed` 传给 provider；progress 报告 `(index + prior, total + prior, index + prior)`，分母变成 listing 全集，分子累计。
- 在 `_land_dataset` 开头（fetch 前）stderr 打一行头注：`daily_bars: 已跳过 1400 只已落地标的，本次 fetch 4168 只`——这样用户第一眼就看到 skipped 不再 hidden。
- 验证：stub 模拟 4 只 wanted、前 2 已落地 → progress calls `[(3, 4, 3), (4, 4, 4)]`，头注 `已跳过 2 只已落地标的，本次 fetch 2 只`。
- 边界测试：lifecycle 用 stub provider 都得接 `prior_landed`，否则 CLI 调用 `TypeError`。已批量改 6 处 stub。
- 沙箱坑：`tmp_path` broker EEXIST 是已知环境问题，1 个 lifecycle 测试须 `--deselect`，非本次改动引入。
- 改动文件：协议 `src/astock_lens/data/contracts.py`、provider `akshare/westock_bars/westock/neodata/local.py`、`sync.py` 头注、test mock `test_raw_sync.py`/`test_cli_lifecycle.py`。
- ruff/mypy 全过；akshare 16/16、westock_bars 12/12、raw_sync 19/19、cli_lifecycle 41/41（1 个 broker 受阻 deselect）。
