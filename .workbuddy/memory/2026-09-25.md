# 2026-09-25

## 数据源替代切片：接入 a-share-data-lake_v1 本地日线（LakeProvider）

### 背景与裁决

用户问：项目数据源能不能替代。分析结论（同会话内实测对齐）：

1. **集中风险**：westock-cli（日线+财报）、neodata（估值/行业/语义）、akshare（名单+日线回退）三条链路的底层都是腾讯行情接口。腾讯一旦断，全断。本机代理已经掐掉 eastmoney push2（akshare docstring 有记录），AkShare 日线已经"被迫走腾讯域名"，所以这个集中不是假设，是事实。
2. **neodata 是最脆弱的一环**：12 小时 token 过期、WorkBuddy 平台侧人工刷新、意图匹配（服务端意图模型升级即静默 1001）、批量回答不完整（3 只请求只回 1–2 只）。这些不是设计缺陷，是"把关键主数据押在一个不可控外部服务上"的必然后果。
3. **westock-cli 的防御清单就是它的脆弱性证明**：模块 docstring 里记录了五条实测坑（batch summary 谎报成功、返回列随批次内容变化、5576 只里 58 只被静默跳过等）。
4. **数据湖可承担"日线+名单"的方向已选定**：数据湖 Phase1 已收官（2026-09-25），本机已有 805 万行不复权/前复权日线、5798 只主档（含 224 只退市）、交易日历、涨跌停、停牌、8 只基准——是一个已经核对过、可离线的 bulk 源。

### 本切片做什么、不做什么

- **做**：`LakeProvider` 只替代日线，作为 `ASTOCK_BULK_PROVIDER=lake` 的第三种选择。同时实现 `BatchMarketBarSource` + `SymbolBarFallbackSource`，把 `sync-bootstrap`/`sync-research` 之前写死的 `batch_source=None` 接成真的批量。
- **不做**：名单不迁。数据湖主档只有 `code/name/list_date/delist_date`，给不出归一层必填且非空的 `is_st / is_delisting_board / suspended_trading_days`（ST 只有当前快照名，不是 PIT）。硬接等于把 ST 规则建立在猜值上，违反 AGENTS.md 红线。名单仍由 AkShare 提供。
- **不做**：财报、估值、行业不动。财报 PIT 三源对账（Baostock pubDate vs WeStock InfoPublDate vs iFinD）是另一个切片。
- **不做**：不引入新的阈值或限速策略（AGENTS.md：`Deferred`）。

### 单位对齐（实测）

用同一标的同一交易日对账 WeStock 落地文件与数据湖：
- close、amount 完全吻合（茅台 2024-01-02 close=1685.01、amount≈54.4 亿元两边一致）
- volume 数据湖 = 落地文件 × 100——落地是 AkShare 未换算的"手"，数据湖是"股"。WeStock 代码 ×100 落 Raw，恰好与数据湖同单位（**Raw 层 volume=股、amount=元**，与 §6 规范一致）

结论：数据湖原样吐出不需要任何换算。`turnover_rate` 数据湖没有，但没有任何因子消费它（流动性因子是 `avg_amount_20d`，读 amount），留空即可。

### 契约与实现

- `src/astock_lens/data/providers/lake.py`：`LakeProvider`，构造接受 `path` 或 `ASTOCK_LAKE_DAILY_PATH` 环境变量，无默认（不猜兄弟目录）。
- `fetch(daily_bars)` 单日、`fetch_recent_bars(BootstrapBatchRequest)` 整段窗口、`fetch_symbol_bars(symbol)` 逐标的补缺——三种"没取到"分开：ValueError 是调用方问题；SOURCE_ERROR 是 Parquet 不存在/读失败；NULL 是那天/那段没行；missing_symbols 是请求了但湖没回。绝不伪造、绝不静默补 0。
- 列顺序复用 `BAR_EMIT_COLUMNS`（westock_bars 里已定义），保持单一真源。
- pyarrow.dataset 谓词下推，全市场单日读 800 万行 parquet 亚秒级。

### CLI 接线

- `runtime._bulk_provider` 新增 `lake` 分支，无进度回调（本地读不需要）。
- `runtime._listing_provider`：lake 也只服务日线，名单仍走 AkShare（与 westock-bars 同规则）。
- 新增 `runtime._batch_source(provider)`：以 `hasattr(provider, "fetch_recent_bars")` 为判据，把批量源接进 bootstrap；westock/akshare 依旧返回诚实的 `None`（2026-09-18 的 `NO_BATCH_PRIMARY_AVAILABLE` 结论对它们仍然成立）。
- `sync-bootstrap`/`sync-research` 里 `batch_source=None` 改为 `batch_source=_batch_source(provider)`，注释同步更新——解锁前提是"经过证据背书的批量日线源已经存在"，也就是本次的 lake。

### 测试与验证

- `tests/unit/test_lake_provider.py`：17 条失败测试先行（RED → GREEN），覆盖 health/fetch/fetch_recent_bars/fetch_symbol_bars 契约、单位、缺失即缺失（NaN/无行/无文件三态分离）、CLI 接线（`_bulk_provider` 选到 lake、`_listing_provider` 路由 AkShare、`_batch_source` 判 duck typing），加一条 `skipif` 守住的真实湖对账测试（茅台 2024-01-02 close 与 amount 精确匹配）。
- 全量：`1297 passed / 1 failed`。唯一失败是 `test_the_batch_contract_still_fails_as_a_whole`——它在 working tree 修改过的 `akshare_provider.py`（batch-permissive 行为）与测试断言（batch-fails-as-whole）之间存在既有矛盾，与本次切片无关。本切片所有代码路径均通过 lint + format + mypy。

### 新立的约定

- **数据湖 provider 只做日线**：名单/财报/估值/行业不因湖已建就顺手迁移；每一项替换都得单独走"实证对账 → 失败测试 → 实现"的切片。
- **`_batch_source` 是 duck typing**：新加批量日线源时只要实现 `fetch_recent_bars` 就自动接上 bootstrap，不需要改这里——避免"新写一个 provider 还要修 CLI 层"的耦合。
- **`ASTOCK_LAKE_DAILY_PATH` 无默认**：不给"猜一个兄弟目录"的机会，`health()` 在未配置时如实报 `SOURCE_ERROR`，让配置错误和"这个市场没数据"永远分得开。

### 已知遗留（不阻塞本切片）

- 数据湖 volume 是"股"，而 working tree 的 `daily_bars.csv`（历史 AkShare 落地）volume 是"手"——同一个文件里存在两种单位的混用，此前没暴露因为没因子读 volume。等哪天有 volume 因子或做合并落地时，必须显式裁决"以哪一路为准"。这是既有问题，不由本切片引入。
- ST 历史 PIT 与申万行业 PIT 仍是全市场无解，不属 Provider 选型层。
