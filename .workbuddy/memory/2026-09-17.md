### 一、财务数据链路（设计规格 §24 补遗）

按项目所有者批准，把财务三大表的 bulk 源改为**腾讯 WeStock CLI**，理由是实测它同时给出
可靠的 `EndDate`（报告期）与 `InfoPublDate`（公告日期），且支持批量；AkShare/Sina 的
`公告日期` 不是原始公告日（实测同一报告期，资产负债表标 `20260815`、利润表标 `20260417`），
无法单独承载时点规则。

链路：`WestockCliProvider → Raw（逐字表格）→ FinancialStatementNormalizer（49 个指标）
→ FinancialQualityGate → FinancialObservation → 基本面因子`。

关键实现约定：

1. `available_at` = 公告日当天的 A 股收盘（15:00 +08:00），保守取值，宁可晚不可早。
2. 缺失分三类且不互相冒充：源站空值 → `NULL` 观测；值读不出 → 失败记录 + `INVALID`；
   某张表**没落地** → `absent_datasets` 点名。
3. 合并键：名单按 `symbol`、日线按 `(symbol, trade_date)`、财报按 `(code, EndDate)`。
4. 全市场实测（5,576 只 × 三大表）：37 分钟、168 次调用、缺口 4–6 只（退市/B 股，
   项目所有者确认不再处理）；归一化 92 秒、峰值内存约 2.9 GB、0 个阻断问题。

全市场运行暴露出三个只有真实规模才能发现的缺陷，均已修复：

- 源站列集**随批次内容变化**（含银行多 6 列、含保险多 7 列），原实现判为"形状损坏"而整表放弃；
  现按**列的并集**合并，缺失单元格留空（= 缺失，不是 0）。文件合并层同样改为并集扩展。
- 批次成功也可能**静默漏代码**（58/5,576），现对 `missing_symbols` 做一次补抓，缺口降到 4 只。
- 失败原因原先被丢弃，现由 `RawDataset.message` 承载并出现在落地报告里。

### 三、权重评审（同日）

新建 `WeightedPercentileScanner`（权重的**符号表达极性**：负数表示越小越好）与评审工具
`scripts/review_strategy_weights.py`，用真实全市场数据把候选方案的结果摊开。

评审结论：

- Quality 的权重**真的决定看到谁**（等权 vs 收益+现金流优先，top-12 仅 3 个重合）；
  Growth/Dividend 换权重几乎无效（88% 重合），因为被极端值主导。

## 七、Value/GARP 权重裁决与负比值政策（同日，所有者"按推荐来"）

### 已执行

1. **Value 取等权**：`pe_ttm -1 / pb -1 / ps_ttm -1 / pe_percentile -1 /
   pcf_operating_ttm -1 / roe_ttm +1`（评审显示三套权重 top-8 重合 75%）。
2. **GARP 取等权**：`peg -1 / pe_percentile -1 / revenue_cagr_3y +1 /
   net_profit_parent_cagr_3y +1 / roe_ttm +1`（评审显示 top-6 重合 83%–100%，
   因为 GARP 的资格约束本身很强）。
3. **负比值政策：比值不存在时判 `NOT_APPLICABLE`**：
   - 源站倍数非正（负现金流/负净资产/负增长）→ `NOT_APPLICABLE`；
   - 基本面比值分母非正（亏损、负权益）→ `NOT_APPLICABLE`（原先报 `INVALID`）；
   - 百分位不受约束（`0.000` 是合法的"最便宜分位"）。

执行后 **6/7 个 Scanner 在打分**（momentum/growth/quality/dividend/value/garp），
只剩 `industry_trend` 等行业数据归一化。

### 新查出的疑点（未解决）

**源站 PEG 值域是 83–1503**（正常 PEG 在 0–5）且会出现负值，说明定义/尺度与常见口径不同。
方向仍可用（越低越匹配），但绝对值不可与外部 PEG 比较。备选方案：用我们已有的

## 九、neodata 落地与管线接线（同日收尾）

- **落地格式**：`<raw>/neodata/<dataset>/<取数日>.csv`，内容块逐字副本（列 `type,desc,content`）。
  一天一个文件——多行文本合并会破坏溯源；同日重跑覆盖、异日各自留档；
  时点选择 = "不晚于 as_of 的最新一天"，未来文件不可见（有测试）。
- **管线**：新增 `stages.valuation_inputs`，`normalize_stage` 把估值观测并进因子上下文；
  `DatasetIndex` 已按标的切分估值。`source_file` 为 None = 还没同步（与"没有估值"区分）。
- **命令行**：`astock sync --as-of D --valuation --symbol X --symbol Y`。必须显式给 symbol
  （neodata 不枚举 + 估值批量覆盖极低），**缺参数立刻报错**——这条 fail-fast 是一次
  36 秒测试暴露出来的（原实现在抓完几十秒行情后才校验）。
- **真实验证**：落地 2 块 → 230 条观测 → Value 打分：平安银行 83.33（rank 1.0）、
  茅台 66.67（rank 0.5）。`stock` 画像显示 pe_ttm 19.31、pb 6.26、pe_percentile 3.39%。
- 测试 604 passed；CLI 测试文件从 115 秒回到 9 秒（打桩 + fail-fast）。
