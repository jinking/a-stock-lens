# 2026-09-17 — a-stock-lens

## 本次会话交付

承接 2026-09-16 的设计一致性实现，本次完成三段：财务数据链路、Scanner 资格判定、权重评审。

### 一、财务数据链路（设计规格 §24 补遗）

按项目所有者批准，把财务三大表的 bulk 源改为**腾讯 WeStock CLI**，理由是实测它同时给出
可靠的 `EndDate`（报告期）与 `InfoPublDate`（公告日期），且支持批量；AkShare/Sina 的
`公告日期` 不是原始公告日（实测同一报告期，资产负债表标 `20260815`、利润表标 `20260417`），
无法单独承载时点规则。

链路：`WestockCliProvider → Raw（逐字表格）→ FinancialStatementNormalizer（49 个指标）
→ FinancialQualityGate → FinancialObservation → 基本面因子`。

关键实现约定：

1. `available_at` = 公告日当天的 A 股收盘（15:00 +08:00），保守取值，宁可晚不可早。
2. 缺失分三类且不互相冒充：源站空值 → `NULL` 观测；值读不出 → 失败记录 + `INVALID`；
   某张表**没落地** → `absent_datasets` 点名。
3. 合并键：名单按 `symbol`、日线按 `(symbol, trade_date)`、财报按 `(code, EndDate)`。
4. 全市场实测（5,576 只 × 三大表）：37 分钟、168 次调用、缺口 4–6 只（退市/B 股，
   项目所有者确认不再处理）；归一化 92 秒、峰值内存约 2.9 GB、0 个阻断问题。

全市场运行暴露出三个只有真实规模才能发现的缺陷，均已修复：

- 源站列集**随批次内容变化**（含银行多 6 列、含保险多 7 列），原实现判为"形状损坏"而整表放弃；
  现按**列的并集**合并，缺失单元格留空（= 缺失，不是 0）。文件合并层同样改为并集扩展。
- 批次成功也可能**静默漏代码**（58/5,576），现对 `missing_symbols` 做一次补抓，缺口降到 4 只。
- 失败原因原先被丢弃，现由 `RawDataset.message` 承载并出现在落地报告里。

### 二、Scanner 资格判定

Growth / Quality / Dividend 三个 Scanner 先只做**资格判定**（设计把权重与评分阈值列为
`Deferred`，打分会是没人评审过的判断）；Value / GARP 因缺估值口径、Industry Trend 因缺行业
数据而暂不实现，注册表会写明各自等待的输入。

### 三、权重评审（同日）

新建 `WeightedPercentileScanner`（权重的**符号表达极性**：负数表示越小越好）与评审工具
`scripts/review_strategy_weights.py`，用真实全市场数据把候选方案的结果摊开。

评审结论：

- Quality 的权重**真的决定看到谁**（等权 vs 收益+现金流优先，top-12 仅 3 个重合）；
  Growth/Dividend 换权重几乎无效（88% 重合），因为被极端值主导。
- 查出两个因子缺陷：`dividend_payout_ttm`、`ocf_to_net_profit` 的分母（TTM 归母净利润）
  接近 0 时比值爆炸，榜首支付率高达 6407%；Growth 榜首 `revenue_yoy` 1819%、
  `net_profit_parent_yoy` 71528%。

### 四、项目所有者裁决（本次已执行）

1. **三个 Scanner 采用等权开启打分**（Quality：`debt_to_asset` 取负号）。
2. **Dividend 改用源站的 `DividendPaidRatio`**（实测正常：茅台 79.00%、平安银行 27.13%），
   不再用 TTM 比值参与排名；原因子保留为证据但不进 `required_factors`。
3. **Growth 暂不做稳健化处理**，该决定保持开放并记录在案。
4. **文档与提交信息一律使用中文**（所有者明确要求）。此约定已写入 `AGENTS.md`，
   从此每次切片都要遵守；历史提交保持英文不改写。

## 五、neodata 定位修订（同日，项目所有者指出应按重要性评估）

我原先判断 neodata"只适合候选级"，理由（逐标的 / Markdown / 凭证过期）被实测推翻两条：

- **可批量**：10 只标的一次查询返回 10 行（3.1 秒）；
- **形态不是障碍**：本仓库已为 WeStock 实现了 Markdown 表格解析。

凭证缓存位置已由 v1.6.0 插件迁移到
`~/.workbuddy/plugins/cache/*/finance-data/*/skills/.neodata_token`，旧路径只是兜底；
刷新由所有者在 WorkBuddy 侧完成，Provider 负责如实报告状态。

实测能力（决定它能做哪些主数据）：估值含**历史分位**与**行业相对标签**、逐日股息率/EV/PEG；
行业含**板块估值 + 完整成分股明细**（这是全市场估值的批量路径：按板块迭代而非 5,500 次
单标的查询）；单季财报一次 8 期且**历史行带"最新调整"标记**（时点卫生优于 westock）。

仍然成立的三条限制（写进 Provider 与设计补遗 §24.1）：

1. 意图匹配决定能否取到数据（未命中返回 `1001`），查询措辞固化为模板；
2. **批量回答是部分的**：请求 3 只时利润表只回 2 只、估值只回 1 只，而 `apiData.entity`
   三只都列——覆盖必须按内容判定并补抓一次，不能信 entity；
3. 不做标的枚举，名单仍由 AkShare 提供。

分工定为：**估值 / 行业 / 语义三维度用 neodata 做主数据；财务三大表以 WeStock 为主、
neodata 作交叉验证；名单与日线仍走 AkShare + WeStock。**

本次已实现：`data/providers/neodata.py`（查询模板、批量、缺口补抓、`missing_symbols`、
失败原因入 `message`）、凭证三级解析（环境变量 → 插件目录取最新 → 旧路径）、
`astock doctor` 报告状态、三条真实响应的离线 fixture 与 16 个测试。

下一步：估值与行业数据的归一化层，随后解锁 Value / GARP / Industry Trend 三个 Scanner。
